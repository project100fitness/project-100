# Motion review and CREAMi colour choices

The CREAMi gallery is now manual, removing the pause/resume button, timer and extra status row. Native horizontal swiping/scrolling, Previous/Next arrows, a count and View all share one compact row. Existing readable recipes, full posters, zoom, original cookbook and page reader are retained.

The popup header has one native Colour disclosure. Three labelled radio choices select Berry & Vanilla, Blueberry Cream or Caramel Cocoa. The choice is stored locally and applied to the shell and isolated guide through the existing private MessageChannel. Each palette has readable light/dark tokens. The main website's light/dark setting remains independent. The menu uses native keyboard controls, Escape closes the menu first and choices remain available without adding a row of permanent colour buttons.

The animation audit reproduced vector cards turning while global motion was paused, and title shimmer continuing under global pause and reduced motion. The original flip-card controller now observes pause, current motion preference, keyboard exploration and dialogs. The existing core motion controller distributes live reduced-motion changes through its authored event. HUD shimmer, scanning and mobile sheen follow the motion state; reduced-motion rules remove them. Journal indicators, tilt and Kinetics scanning/source scrolling also respect reduced motion. Exercise entry previews hold during keyboard focus. Continuous meal-photo animation follows the same authored motion setting.

Source changes are confined to original component owners and their versioned HTML dependencies. No repair stylesheet, global API monkey patch or user-agent workaround was introduced. Source images, recipe quantities, current book records and hosted media are unchanged. All 37 local video assets have no audio track. Raster inventory found no inherently animated images. Videos in native disclosures are deliberately loaded only after the section is expanded; tests use the real disclosure controls.
